# Halaman Otomatisasi

Halaman `/dashboard/automation` berada di sidebar, dengan tautan ke Audit Trail. Kontrak tampilan: judul dan aksi perbarui di atas, dua panel scheduler, ringkasan eksekusi akun, lalu tabel riwayat dengan filter pemicu. Gunakan token/typography SIBA yang sudah tersedia. Panel bertumpuk pada layar kecil; tabel dapat digulir mendatar. Label status tidak hanya dibedakan melalui warna. Loading, kosong, error, data parsial, dan pembaruan tertunda ditampilkan secara eksplisit. Pemeriksaan visual diserahkan kepada pengguna sesuai permintaannya.

Halaman membaca `get_automation_status()` setiap 30 detik ketika terbuka. RPC memerlukan akun terautentikasi, membaca jadwal dua job SIBA, membatasi run/pesan ke `auth.uid()`, dan tidak mengembalikan perintah Cron, kredensial, chat ID, atau isi pesan. Run dibatasi 50 dan pesan terbaru 100; agregasi status pesan per run menghitung seluruh outbox terkait, bukan hanya 100 pesan tersebut. Riwayat lama memakai sumber `unknown` dan tidak diberi hubungan run/pesan yang ditebak.

Migration `20261008120000_automation_monitoring.sql` menambah `automation_runs`, hubungan audit/outbox, RPC, serta penanda `trigger_source=cron` pada URL job workflow yang sudah ada. Waktu/jadwal/headers/key Cron dipertahankan. Workflow memverifikasi autentikasi sebelum membaca penanda tersebut. Penanda menunjukkan jalur panggilan yang dinyatakan oleh pemanggil server terautentikasi; bukti eksekusi otomatis tetap disandingkan dengan history Cron. Pemanggil yang memiliki kunci server juga dapat memanggil URL berpenanda secara manual, sehingga penanda bukan bukti independen tanpa history scheduler.

Workflow mencatat RUNNING untuk setiap akun yang diproses, lalu SUCCESS/PARTIAL/INCOMPLETE/FAILED. Preview Telegram juga dicatat sebagai manual dengan mode preview. Run yang terhenti tanpa hasil akhir tidak dianggap berhasil/gagal; setelah 10 menit halaman menampilkan “Belum ada hasil akhir”. Kegagalan sebelum daftar akun tersedia atau sebelum autentikasi tidak dapat ditautkan ke akun dan tidak menciptakan run. Status sukses Cron hanya berarti perintah pemicu selesai; HTTP workflow dan status sent Telegram merupakan hasil yang berbeda.

Jadwal berikutnya dihitung untuk pola harian kerja dan per-menit yang terpasang, dengan timezone UTC/GMT dari server. Pola lain atau timezone lain ditampilkan sebagai ekspresi asli tanpa mengarang next run. Penulisan `00 00` dan `0 0` diperlakukan sama. Jadwal Senin–Jumat tidak mencakup kalender hari libur bursa.

Verifikasi kode: `npm test`, `npm run build`, `npm run build:workflow`, `npx deno check --no-lock supabase/functions/siba-workflow/index.ts`. Setelah migration, validasi RPC dengan konteks akun dan cek privilege anon/write authenticated. Tidak ada data contoh yang disisipkan untuk mengisi halaman. Riwayat otomatis/manual baru baru muncul ketika workflow benar-benar berjalan setelah versi monitoring dipasang.
